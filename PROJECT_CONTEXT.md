# LinguaFlow 2.0 — контекст проекта

Обновлено: 19 октября 2026 года. Этот документ описывает текущую реализацию и решения из истории проекта. Подробные примеры API — в README.md; при расхождении приоритет имеет код.

## Расположение и назначение

- Рабочая папка: `C:\Users\propi\Documents\PDF TRANSLATION\ai translation 2.0`.
- Репозиторий: https://github.com/propilen/ai-translation-2.
- Соседняя папка `ai translation` — другой экземпляр. Изменения этого проекта нужно делать именно в `ai translation 2.0`.
- Локальный веб-сервис перевода документов с помощью LLM, память переводов TMX/SQLite и отдельный прототип XLIFF-редактора.
- Основной стек: Python/FastAPI, SQLite, обычные HTML/CSS/JavaScript. Переписывание на Rust/Go не выполнялось.

## Карта исходников

- `backend/app.py`: FastAPI, авторизация запросов, страницы, задания перевода, административные API.
- `backend/auth.py`: пользователи, пароли, подписанные cookie-сессии, API-ключи и их права.
- `backend/config.py`: параметры LLM и рабочей папки, загрузка/сохранение настроек.

- `backend/model_client.py`, `gemini_client.py`: обращения к моделям; `nlp_glossary.py`: терминология.
- `backend/translation_memory.py`: импорт TMX, сегменты SQLite, поиск, индексы, экспорт TMX.
- `backend/memory_api.py`: API памяти переводов и раздача страницы memories.
- `translate.html/css`, `settings.html/css`, `admin.html/css`: основной интерфейс.
- `memories.html/js/css`: мастер импорта, поиск, результаты, скачивание.
- `app-navigation.js`, `app-nav.css`, `assets/`: общая навигация, логотип и иконки.
- `xliff-editor/`: самостоятельный FastAPI + React/Vite/TypeScript редактор; инструкции в его README.md.
- `nlp-worker/`: отдельный JSON Lines процесс для Java Desktop; импортирует неизменённый `backend/nlp_glossary.py`, держит модели и глоссарии в памяти. Windows standalone сборка Nuitka, Java 25 клиент, регрессионные тесты и команды — в `nlp-worker/README.md`. Веб-сервис продолжает вызывать NLP напрямую.

## Запуск и конфигурация

Основной сервис использует Python 3.11 и зависимости из `requirements.txt`. Для полного перевода нужны Java/Okapi Tikal и модели spaCy `en_core_web_sm`, `de_core_news_sm`. Запуск: `.venv\Scripts\python run_server.py`. По умолчанию адрес — `127.0.0.1:8000`, uvicorn работает с reload.

`start_server_2_0.bat` задаёт порт **8001** и `TRANSLATION_WORKSPACE=C:\ai_trans_2_0`. Это отличается от запуска `run_server.py` без переменных: порт **8000**, рабочая папка по умолчанию `C:\ai_trans`. В истории разработки использовался адрес `http://127.0.0.1:8000/memories.html`, а рабочая память находилась в `C:\ai_trans\memories`. Не считать папку кода источником истины о расположении баз — проверять эффективные настройки.

`TRANSLATION_SETTINGS_FILE` переопределяет файл настроек, иначе это `service-settings.json` в исходной рабочей папке. Сохранённый `workspace_root` определяет каталог заданий и памятей. Настройки могут содержать API-ключ модели: не выводить файл целиком и не коммитить его.

`LINGUAFLOW_DATABASE` задаёт базу пользователей; по умолчанию `data/linguaflow.db` внутри проекта. Рядом хранится `session-secret.bin`. При новой установке код создаёт администратора admin/admin; пароль следует изменить через администрирование.

Отдельный XLIFF-редактор запускается `start_xliff_editor.bat`: API 8001, Vite 5173. Порт API конфликтует с `start_server_2_0.bat`, если запускать их одновременно. Не менять порты молча; согласовывать конфигурацию клиента и сервера.

## Интерфейс и предпочтения пользователя

Язык интерфейса — русский. Пользователь явно просил сохранять общую шапку, логотип, фон, типографику и существующие стили. Новые компоненты должны использовать текущие светлые карточки, синие основные кнопки, лавандовые вторичные кнопки, тонкие рамки и компактные элементы.

`memories.html` объединяет «Поиск по памяти» и «Импорт TMX» в одной карточке с двумя вкладками. По умолчанию открыт поиск; `#search`/`#import` сохраняют выбор при перезагрузке. Есть управление вкладками стрелками, Home/End. Глобальная навигация и заголовок страницы сохранены.

Поиск: выбор памяти, оригинал и перевод, режим, порог, регистр и регулярные выражения непосредственно в текстовых полях. Enter запускает поиск, Shift+Enter вводит перенос. Оба заполненных поля должны совпасть. Результаты — компактная таблица с номером сегмента, оригиналом, процентом/режимом и переводом. Языки показываются по памяти. Есть подсветка запроса, выбранной строки, кнопки копирования в ячейках. Рядом расположены «Скачать TMX» и «Скачать SQLite».

Импорт: три шага — файл, параметры, проверка. Можно создать новую память или дополнить существующую. Для существующей памяти поля названия/описания/языков подставляются и блокируются. Пары оригинал–перевод не дублируются, неправильные/пустые языковые варианты пропускаются.

## Память и поиск

Каждая память — отдельный `{uuid}.sqlite` в `<workspace_root>/memories`. Таблица `metadata` содержит JSON, `segments` — `id`, `tuid`, `source`, `target`, `normalized`, `author`, `created_at`. Уникальность задана по `(source, target)`. `author` необязателен; API задаёт дату создания автоматически в UTC. У старых записей после миграции метаданные могут оставаться NULL. Дубликат не заменяет существующую пару и её метаданные. Один оригинал с другим переводом создаёт отдельный сегмент.

Поиск: `mode=fuzzy|words|phrase|all`, по умолчанию fuzzy; `threshold=70`, `limit=50` (1–200). `source_q`, `target_q`; совместимость `q` для оригинала. `respect_case=false`, `use_regex=false`. Regex использует синтаксис Python. Выдача включает `score`, `exact`, `matched_modes`; words/phrase/regex возвращают `score=null`. Fuzzy считает Indel-сходство RapidFuzz, не семантическое сходство.

Добавлены FTS5 unicode61 для слов/фраз и trigram для кандидатов Fuzzy. Индексы автоматически строятся и поддерживаются триггерами INSERT/DELETE/UPDATE. Версия индекса — `PRAGMA user_version=2`. При отсутствии поддержки FTS предусмотрен полный просмотр. WAL, synchronous=NORMAL и busy_timeout=5000 включаются в операциях памяти.

Измерение 10 октября 2026: 42 047 сегментов, 20 пробных Fuzzy-запросов; результаты совпали с полным перебором, суммарное ускорение около 7,5 раза, слова/фразы — несколько миллисекунд. Построение индекса ~7,3 с, размер ~26 → 53 МБ. Это локальный замер, не гарантия для других данных.

## API памяти переводов

Сессия пользователя либо `Authorization: Bearer lf_tm_...` / `X-API-Key`. API-ключи ограничены маршрутами памяти. `can_read` разрешает чтение, `can_write` — изменения. Ключ может охватывать все памяти или одну.

| Метод | Назначение |
| --- | --- |
| GET `/api/memories` | Список доступных памятей |
| POST `/api/memories` | multipart TMX: document, source_language, target_language, необязательные name, description, existing_memory_id |
| GET `/api/memories/{id}/search` | Поиск по оригиналу/переводу |
| POST `/api/memories/{id}/segments` | JSON source, target, необязательные tuid, author; возвращает id, metadata, added, duplicate |
| DELETE `/api/memories/{id}/segments/{segment_id}` | Удаление: 204, отсутствующий сегмент: 404 |
| GET `/api/memories/{id}/download` | SQLite |
| GET `/api/memories/{id}/download-tmx` | Потоковый TMX 1.4 |

TMX экспортирует текст и языки, tuid (или внутренний id), автора как creationid, дату как creationdate. XML экранируется. Исходная inline-разметка TMX при импорте не сохраняется; экспорт — PlainText.

## Администрирование ключей

В `/admin` есть раздел «Памяти переводов»: создание ключа для всех памятей/одной памяти, «Изменить» и «Отозвать». Модальное редактирование содержит название, память, новый секрет, права «Чтение» и «Запись». Созданный ключ по умолчанию только читает. Пустое поле нового секрета сохраняет старый; замена секрета инвалидирует прежний ключ. Хотя бы одно право обязательно. Пояснения к правам заключены в скобки.

- GET/POST `/api/admin/memory-api-keys`, PUT/DELETE `/api/admin/memory-api-keys/{id}` — cookie-сессия администратора.
- GET/POST `/api/auth/api-keys`, DELETE `/api/auth/api-keys/{id}` — собственные ключи пользователя.
- PUT принимает name, memory_id/null, can_read, can_write, secret/null.
- Секреты хранятся SHA-256-хешами, пароль пользователя — PBKDF2. Секрет ключа нельзя повторно получить из списка.

## Проверка и известные ограничения

Основная команда: `.venv\Scripts\python -B -m unittest discover -s tests -v`. На последней проверке — 19 тестов. Они покрывают импорт, поиск и режимы, API, доступ через сессии, сегменты, TMX-экспорт, восстановление индексов. JS: `node --check memories.js`. Проверки интерфейса в истории были преимущественно статическими; не считать их полноценным браузерным тестированием.

Для редактора — отдельные команды из `xliff-editor/README.md` (backend tests и npm run build). Не считать тесты основного сервиса проверкой редактора.

Технические ограничения, которые важно учитывать при следующих изменениях:

1. Fuzzy отбирает ограниченное число кандидатов по bm25 (300–2000, зависит от limit); это эвристика. Возможны пропущенные совпадения, в том числе без общей триграммы. Совпадение 20 тестовых запросов не доказывает полноту. При threshold < 50 и коротких запросах выполняется полный просмотр.
2. Unicode-нормализация Python и токенизация FTS отличаются; проверять необычные символы и регистр при изменениях поиска.
3. SQLite скачивается из основного файла после WAL checkpoint. Это не гарантированно согласованный снимок при параллельной записи; для надёжного экспорта стоит использовать SQLite backup API во временный файл.
4. Импорт TMX пока не переносит creationid/creationdate в автора и историческую дату: автор NULL, дата — время импорта. При экспорте и повторном импорте эти метаданные не сохранятся полностью.
5. Проверка области ключа в POST /api/memories сравнивает scope с existing_memory_id даже для глобального ключа. Поэтому дополнение существующей памяти глобальным ключом может ошибочно вернуть 403. Прямой POST /segments использует отдельную корректную проверку scope.
6. id — INTEGER PRIMARY KEY без AUTOINCREMENT; удалённый максимальный id может использоваться снова. tuid не уникален. Отдельного PUT для редактирования сегмента пока нет.
7. Миграции/создание индексов выполняются при обращении; первый запрос может быть долгим. Режим WAL требует локального совместимого файлового хранилища.

## Git и перенос на другой компьютер

В Git хранятся исходники, зависимости/lock-файлы, стили, иконки, фильтры Okapi, тесты и документация. `.gitignore` исключает окружения, node_modules, базы, секреты, документы пользователя, TMX/XLIFF и временные артефакты. Синхронизация Git не является резервным копированием памятей, пользователей и документов. Для переноса данных нужны отдельные согласованные копии баз и настроек; секреты в репозиторий не добавлять.
